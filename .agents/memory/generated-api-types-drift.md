---
name: Generated API types can silently drift from hand-written Zod schemas
description: This repo manually maintains generated-looking files (no orval codegen) in lib/api-zod and lib/api-client-react; they can fall out of sync with each other and with actual route implementations.
---

- `lib/api-zod/src/generated/api.ts` (Zod schemas) and `lib/api-client-react/src/generated/api.schemas.ts` (TS interfaces) are hand-maintained in parallel — they are NOT guaranteed to match each other. A field can exist in one and not the other (e.g. `AdminStats` had extra fields in the Zod schema that the TS interface was missing).
- A stray `lib/api-zod/src/generated/types/` directory was found duplicating `api-client-react`'s TS interfaces inside `api-zod`, causing TS2308 ambiguous re-export errors from `lib/api-zod/src/index.ts` exporting both `./generated/api` and `./generated/types`. `api-zod` should only export Zod schemas/validators, not plain TS interfaces.
**Why:** These files look auto-generated (have "Generated by orval" headers) but orval is NOT actually run in this repo — edits must be made by hand in both places whenever an endpoint's shape changes.
**How to apply:** When a typecheck error says a frontend page references a field missing from a generated interface, but the backend route actually returns/uses that field, first check whether the *other* generated file (Zod schema in api-zod, or vice versa) already has it — the fix is usually just syncing the interface, not changing the route.
